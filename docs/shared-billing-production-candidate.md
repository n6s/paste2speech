# Public shared-credit production release

Roger approved public promotion on October 11, 2026, a fresh shared wallet, a one-time 100-credit owner testing grant, and removal of artificial app spending ceilings. Public opening uses `PUBLIC_LAUNCH_OPEN=1`; verified customers may purchase and use paid OCR/speech. Staging retains its sandbox catalog, separate database and owner provider permits.

## Approved catalog and rates

Live Paddle product `pro_01m4p9ggf6sm4hy4nz41hqjmnf` (PasteToSpeech — Shared balance), active Standard digital goods; live price `pri_01m4p9rrgrcwscvx2q0bqwc00j`: **$10 USD for 1,000 shared credits**, one-time, quantity minimum/maximum one, excludes applicable checkout taxes, no local-price overrides/trial/subscription. Created through Roger’s signed-in Chrome; creation success and active catalog verified. No automatic refill or scheduled credit expiry.

Each credit is 1,000 integer ledger units. Successful speech consumes one unit per Unicode character (one credit per 1,000 characters), including spaces/punctuation in cleaned text. OCR consumes 2,000 units (two credits) per submitted page only after complete validated whole-file output is privately saved. Failed/unstarted speech and unsuccessful OCR release customer holds; uncertain attempts never silently redispatch. Summary creation, browser voices, local PDF extraction, prepared audio and saved OCR replay remain free. Speech of summaries/scanned text uses the normal speech rate.

No account/payment/provider security setting or credential changes.

## Limits audit

Removed: OCR’s $10 cumulative app ceiling and shared/legacy pack-sales restrictions tied to unused-credit backing; speech’s 2,500,000-character daily / 12,500,000-character monthly app ceilings (historical estimates $10/day and $50/month). These are artificial app policy, not provider quotas. New production configuration records unlimited app spending as NULL. Usage remains recorded; finite prepaid customer balance/holds/debt still gate dispatch.

Retained: Google’s **5,000 UTF-8 bytes per synthesis request**, bounded provider output, authentication/verified identity, per-IP rate controls, finite speech preparation concurrency/retries/backpressure, and one active OCR attempt per account. [Official Google quotas](https://docs.cloud.google.com/text-to-speech/quotas), checked October 11, list 5,000 bytes as a non-increasable content limit and generic synthesis default 1,000 requests/minute/project; actual project quotas may differ. No quota increase was requested.

OCR’s current **6 MB / 10-page per-file** technical limits remain for this launch. [Official Mistral OCR FAQ](https://docs.mistral.ai/studio/document-processing/basic_ocr) supports uploaded files up to 50 MB / 1,000 pages. Raising the app toward those requires a separately validated change to the page CHECK, ten-page SQL settlement validation, PDF verifier, whole-file base64/provider output and browser memory handling. This architectural expansion does not block public shared billing. Live Mistral model stays pinned to `mistral-ocr-4-1`; provider/account quotas and outages may still pause service. No provider billing or quota settings were changed, and no billable proof call was made.

## Payments, refunds and deployment

Runtime rejects sandbox credentials, staging database controls, trial/local modes and reused legacy SKU IDs. New shared orders require explicit `offer=credits`; stale speech/OCR purchase requests must refresh. Catalog economics are verified against each completed transaction. Existing signed webhooks and the existing PaymentCoordinator named `unified-v1` settle shared orders plus old speech/OCR orders; no new access or binding is required.

Our additional refund policy offers proportional unused-credit refunds and appropriate remedy for service failures, subject to [Paddle Refund Policy](https://www.paddle.com/legal/refund-policy) and [Buyer Terms](https://www.paddle.com/legal/buyer-terms), including mandatory full refunds/withdrawal rights. [Paddle adjustments](https://developer.paddle.com/build/transactions/create-transaction-adjustments/) can require approval; pending/rejected adjustments do not remove credit. Approved principal adjustments remove exact capped integer units; reversals restore once. Refunds against spent/held units create debt; released unused holds reduce it and later purchases cover debt first. No live purchase/refund was made or promised.
