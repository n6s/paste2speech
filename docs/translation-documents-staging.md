# Staging document translation and quota-aware audio

Translation retains the existing Translate/Summary layout, target selection, original/Edit handling and math speech. English is first/default; other displayed targets are alphabetical. Production remains excluded.

The document plan runs locally and preserves every source codepoint. Pieces target 5,000 Unicode codepoints, preferring paragraph/sentence/word boundaries. A bounded 1 MB manifest transport (900 KB manifest allowance) is an implementation resource envelope; exceptionally large plans fail visibly without truncation. There is no 30,000-character whole-document restriction. Individual Google calls remain below its 30,000-codepoint hard limit. Whitespace-only pieces are retained locally without provider calls or charges.

A durable document reserves the complete 4-credit/1,000-codepoint quote once. Each usable saved piece settles its exact integer units once; no chunk rounding or overlap. Cancel/pause stops new dispatch, permits a claimed piece to finish, and releases the unused hold. Partial results can be copied or used after pausing. Resume reserves only remaining work and reuses saved output. Reload inspects results without starting inference. Abandoned holds pause after five minutes; unresolved dispatched pieces block blind retry and refund their unused hold. Known rejected pieces resume only after an explicit user action. Results expire after 24 hours; financial receipts remain, and a fresh quoted explicit request can regenerate expired output. Existing successful short translations are reused. No server-side source text is stored; only hashes/plan metadata and translated pieces.

Only one active document per account and one in-flight piece per document are admitted. Source/target/account checks protect late responses. The SQL migration is additive and staging guarded; existing wallet rows and receipts must be preserved. Code rollback leaves the additive tables and paid receipts in place; never restore an old wallet backup over new activity.

Offline audio has no fixed 512 MiB or 20-reading cap. Quota estimates are checked with space for growth and a temporary section copy. Actual IndexedDB failures remain authoritative and atomic. Missing estimates allow an attempted write; no previous audio is deleted to manufacture space. Existing temporary retention, user removals, active/export protections, bounded audio RAM and account isolation remain. Reading enumeration avoids holding a duplicate getAll copy of every complete document, but very large queues still incur text/metadata CPU and memory costs. Browser quota is not physical free disk or guaranteed persistence. MP4 assembly, summary and math resource limits are unchanged.

Maintained gates: translation-document(s) unit/client tests, translation-documents-browser.mjs (real synthetic SQLite billing plus mock provider), persistent-audio-browser.mjs, reading-lifecycle-browser.mjs, translation-browser.mjs, full reader release gates and public forced-off checks. No live provider tests are authorized for this iteration.
